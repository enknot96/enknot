AWS Deploy Guide

Next.js アプリの
本番デプロイ完全手順書

Docker化されたNext.jsアプリをEC2にデプロイし、独自ドメイン・HTTPS・GitHub Actionsによる自動デプロイまでを構築する手順書。

ユーザー
　↓
Cloudflare　（DDoS対策 · WAF · CDN · IP隠蔽）
　↓
EC2　t3.micro / Amazon Linux 2023 / 固定IP
　├── Nginx　（リバースプロキシ · HTTPS終端）
　├── Docker　→ Next.js コンテナ（port 3000）
　└── fail2ban　（SSH ブルートフォース対策）
　↑
GitHub Actions　（git push → 自動デプロイ）

Phase 2

AWSアカウント設定

rootユーザーの保護・IAMユーザー作成・請求アラームの設定。

1
rootユーザー MFA設定

右上アカウント名 → セキュリティ認証情報 → 多要素認証(MFA) → MFAを割り当てる → Authenticator app でQRスキャン

2
IAMユーザー作成（管理者）

IAM → ユーザー → ユーザーの作成

項目値
ユーザー名enknot-admin（任意）
コンソールアクセス有効化
グループ新規作成 Administrators
ポリシーAdministratorAccess
3
IAMユーザー MFA設定

IAMユーザーでログイン → セキュリティ認証情報 → MFAデバイスの割り当て

4
請求アラーム設定（$10）

リージョンを us-east-1（バージニア北部）に変更してから作業すること。

請求とコスト管理 → 請求設定 → CloudWatch請求アラートを有効化 → CloudWatch → アラーム → アラームの作成 → メトリクスの選択 → Billing → 概算合計請求額 → USD → しきい値 10 → SNSトピック作成 → 確認メールの Confirm subscription をクリック

Phase 3

EC2構築

仮想サーバーの作成・固定IP取得・ファイアウォール設定。

1
EC2インスタンス作成

EC2 → インスタンスを起動

項目値
名前enknot-server
AMIAmazon Linux 2023
インスタンスタイプt3.micro（12ヶ月無料枠）
キーペア新規作成 enknot-key（.pem）
セキュリティグループSSH + HTTP + HTTPS を許可
ストレージ8GB gp3（デフォルト）
⚠ ダウンロードされた enknot-key.pem は紛失すると再取得不可。必ず保管すること。 
# キーファイルを移動して権限設定
mv ~/Downloads/enknot-key.pem ~/.ssh/
chmod 400 ~/.ssh/enknot-key.pem
2
Elastic IP 取得・割り当て

EC2 → Elastic IP → Elastic IPアドレスを割り当てる → 割り当て → アクション → Elastic IPアドレスの関連付け → インスタンス選択 → 関連付ける

ℹ 割り当て中は無料。インスタンスを停止したまま Elastic IP を保持すると課金される。
3
セキュリティグループ確認

後続フェーズで以下のポートを順次開放する：

ポート用途ソース
22 (SSH)サーバー接続自分のIPのみ（セキュリティ設定フェーズで変更）
80 (HTTP)Nginx0.0.0.0/0
443 (HTTPS)Nginx + SSL0.0.0.0/0
3000Docker確認用（一時的）0.0.0.0/0
Phase 4

サーバー初期設定

EC2にSSH接続してDocker・Gitをインストール。

1
SSH接続
ssh -i ~/.ssh/enknot-key.pem ec2-user@<Elastic IP>
2
パッケージ更新・Docker・Git インストール
# パッケージ最新化
sudo dnf update -y

# Docker インストール・起動・自動起動
sudo dnf install -y docker
sudo systemctl start docker
sudo systemctl enable docker

# ec2-user を docker グループに追加（sudo不要にする）
sudo usermod -aG docker ec2-user

# 一度ログアウトして再接続（グループ反映）
exit

# Git インストール
sudo dnf install -y git
Phase 5

アプリ配置・起動

GitHubからコードを取得しDockerでビルド・起動。

1
GitHubにコードをpush（ローカルMacで実行）
# リポジトリ作成 + push を1コマンドで
gh repo create enknot --public --source=. --remote=origin --push
2
EC2でビルド・起動
# コードを取得
git clone https://github.com/<username>/enknot.git
cd enknot

# Dockerイメージをビルド（2〜5分）
docker build -t enknot .

# コンテナ起動（--restart always = EC2再起動後も自動起動）
docker run -d -p 3000:3000 --name enknot --restart always enknot
ℹ この時点でセキュリティグループにポート3000を一時的に開放すると http://<IP>:3000 で動作確認できる。Nginx設定後は閉じてよい。
Phase 6

Nginx リバースプロキシ

ポート80でアクセスできるようにNginxを設定する。

1
Nginx インストール・起動
sudo dnf install -y nginx
sudo systemctl start nginx
sudo systemctl enable nginx
2
設定ファイル作成
sudo vi /etc/nginx/conf.d/enknot.conf
server {
    listen 80;
    server_name enknot.dev;  # ← ドメイン取得後はドメイン名に変更

    location / {
        proxy_pass          http://localhost:3000;
        proxy_http_version  1.1;
        proxy_set_header    Upgrade $http_upgrade;
        proxy_set_header    Connection 'upgrade';
        proxy_set_header    Host $host;
        proxy_cache_bypass  $http_upgrade;
    }
}
# 文法チェック → 反映
sudo nginx -t && sudo systemctl reload nginx
Phase 7

ドメイン取得（Cloudflare）

1
Cloudflare でドメイン購入

cloudflare.com → アカウント作成 → Domain Registration → Register Domains → ドメイン名を検索 → 購入（約$12/年）

✓ Cloudflare Registrar は原価販売。DNS管理・CDN・DDoS対策も同一画面で完結するため推奨。
Phase 8

DNS設定

1
A レコード追加

Cloudflare → DNS → Records → Add record

TypeNameIPv4 addressProxy status
A@<Elastic IP>DNS only（グレー）← 初期
⚠ Certbot（HTTPS化）完了後にProxy（オレンジ）へ変更すること。初期はDNS onlyにしないとCertbotが失敗する。
Phase 9

HTTPS化（Certbot）

Let's Encrypt のSSL証明書を取得してHTTPS化。

1
Certbot インストール・証明書取得
# Certbot インストール
sudo dnf install -y certbot python3-certbot-nginx

# SSL証明書取得（Nginxに自動設定）
sudo certbot --nginx -d enknot.dev
ℹ 証明書は90日で失効するが、Certbotが自動更新タスクを設定してくれる。手動更新は不要。
⚠ Could not automatically find a matching server block エラーが出たら、/etc/nginx/conf.d/enknot.conf の server_name がドメイン名になっているか確認してから再実行。
2
セキュリティグループにポート443を追加

AWS → EC2 → セキュリティグループ → インバウンドルールを編集 → HTTPS（443）→ 0.0.0.0/0 → 保存

3
Cloudflare Proxy を有効化

Cloudflare → DNS → Records → A レコードの雲アイコンをクリック → オレンジ（Proxied）に変更

Phase 10

GitHub Actions 自動デプロイ

main ブランチへの push で EC2 に自動デプロイ。

1
GitHub Secrets 登録

GitHub → リポジトリ → Settings → Secrets and variables → Actions → New repository secret

# SSH秘密鍵をクリップボードにコピー
cat ~/.ssh/enknot-key.pem | pbcopy
NameValue
EC2_SSH_KEYenknot-key.pem の全内容（%は含めない）
EC2_HOSTElastic IP アドレス
EC2_USERec2-user
2
ワークフローファイル作成
# .github/workflows/deploy.yml
name: Deploy to EC2

on:
  push:
    branches:
      - main

jobs:
  deploy:
    runs-on: ubuntu-latest
    steps:
      - name: Deploy via SSH
        uses: appleboy/ssh-action@v1.0.3
        with:
          host: ${{ secrets.EC2_HOST }}
          username: ${{ secrets.EC2_USER }}
          key: ${{ secrets.EC2_SSH_KEY }}
          script: |
            cd ~/enknot
            git pull origin main
            docker build -t enknot .
            docker stop enknot || true
            docker rm enknot || true
            docker run -d -p 3000:3000 --name enknot --restart always enknot
ℹ Secretsのキー名をサフィックス付き（例: EC2_HOST_enknot）にした場合は、secrets. の参照名も合わせること。
3
main ブランチにpushして動作確認
git checkout main
git merge dev
git push origin main

# Actions の結果を確認
# https://github.com/<username>/enknot/actions
Security

セキュリティ設定

1
SSH IP制限（自分のIPのみ）
# 自分のIPを確認
curl -4 ifconfig.me

AWS → セキュリティグループ → SSH（22番）のソースを <自分のIP>/32 に変更。

⚠ 自宅回線はIPが変わる場合がある。接続できなくなったらAWSコンソールからIPを更新すること。
2
fail2ban インストール・設定
# インストール
sudo dnf install -y fail2ban

# 設定ファイル作成（シンプルな方法）
sudo bash -c 'cat > /etc/fail2ban/jail.local << EOF
[DEFAULT]
bantime = 3600
findtime = 600
maxretry = 5

[sshd]
enabled = true
EOF'

# 起動・自動起動
sudo systemctl start fail2ban
sudo systemctl enable fail2ban

# 動作確認
sudo fail2ban-client status sshd
3
Cloudflare Proxy 有効化

Cloudflare → DNS → Records → A レコードの雲アイコン → オレンジ（Proxied）

✓ 有効化でDDoS対策・WAF・CDN・EC2実IPの隠蔽が自動で有効になる（無料）。
